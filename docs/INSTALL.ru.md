# Установка Internet Health

[English version](INSTALL.md) · Unraid: [INSTALL-UNRAID.ru.md](INSTALL-UNRAID.ru.md)

Internet Health — один образ контейнера, `ghcr.io/d1-m4ss/internet-health`. Он работает на любой машине с Docker, которая всегда включена дома:
мини-ПК или старый ноутбук с Linux, NAS с приложением Docker (Synology Container Manager, QNAP Container Station, TrueNAS, OpenMediaVault, Unraid),
виртуальная машина или LXC в Proxmox, компьютер с Windows или macOS и Docker Desktop. Контейнер запускается, вы открываете веб-страницу и всё
настраиваете там; на машине он хранит только свою папку данных.

> **Пока образ только для x86-64 (amd64).** ARM-устройства — Raspberry Pi, NAS на ARM — его пока не запустят.
>
> **У веб-страницы нет входа по паролю.** Держите порт в домашней сети и никогда не пробрасывайте его в интернет.

## Что нужно машине

- Docker (`docker version` отвечает), для варианта 2 — ещё `docker compose version`.
- Быть в той же сети, что и роутер, лучше по кабелю: Internet Health измеряет подключение **той сети, в которой стоит**. Машина на Wi-Fi
  измеряет заодно и Wi-Fi.
- Около 150 МБ под образ; база растёт примерно на 10–15 МБ в неделю при стандартных целях (срок хранения истории можно ограничить).
- Исходящий интернет для проверок; входящий — только веб-страница в вашей сети.

## Вариант 1: docker run

```sh
mkdir -p ~/internet-health
docker run -d --name InternetHealth --restart unless-stopped \
  -p 8788:8080 \
  -v ~/internet-health:/data \
  -e TZ=Europe/Moscow -e APP_TIMEZONE=Europe/Moscow \
  -e ROUTER_IP=192.168.1.1 -e ROUTER_NAME=Router \
  -e SITES=fast.com,google.com,youtube.com,1.1.1.1,8.8.8.8 \
  ghcr.io/d1-m4ss/internet-health:latest
```

Откройте `http://<адрес этой машины>:8788`.

## Вариант 2: docker compose

Скопируйте [`examples/docker-compose.yml`](../examples/docker-compose.yml) в папку, поправьте значения из таблицы и выполните там `docker compose up -d`.

| Параметр | Что указать |
|---|---|
| `TZ`, `APP_TIMEZONE` | ваш часовой пояс, например `Europe/Moscow` (время ежедневного Speedtest считается по `APP_TIMEZONE`) |
| `ROUTER_IP` | адрес роутера в домашней сети, например `192.168.1.1` (`ip route` в Linux, `ipconfig` в Windows: «основной шлюз») |
| `ROUTER_NAME` | имя роутера на странице и в сообщениях, например `ASUS RT-AX86U` |
| `SITES` | имена **и два IP-адреса**: `fast.com,google.com,youtube.com,1.1.1.1,8.8.8.8`; адреса позволяют отличить «упал DNS» от «нет интернета» |
| `DNS_NAMESERVER_n` / `_IP` | проверяемые DNS-серверы (до 4; по умолчанию Google, Quad9 и Cloudflare); четвёртым можно добавить роутер или Pi-hole / AdGuard |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | необязательно; Telegram можно настроить потом на странице |
| `ports` | поменяйте левое число (`8788`), если порт занят |
| `volumes` | папка данных на этой машине (`./data` — рядом с compose-файлом) |
| `PUID`, `PGID` | необязательно; пользователь, от которого работает приложение (по умолчанию `99:100`). Контейнер стартует от root только чтобы отдать папку данных этому пользователю, затем сбрасывает права; укажите свои числа (`id -u`, `id -g`), если хотите сами открывать файлы, `PUID=0` — работать от root |

Все переменные: [README → Настройка](../README.ru.md#настройка).

## Вариант 3: NAS или другой интерфейс Docker

Любой интерфейс Docker спрашивает одно и то же: создать контейнер из образа `ghcr.io/d1-m4ss/internet-health:latest`, сопоставить **локальный
порт (8788) с портом контейнера 8080**, **папку — с `/data`**, добавить переменные из таблицы выше, политика перезапуска «unless stopped» / «always».
Экран compose / «проект» / «стек» (Synology Container Manager, Portainer, Dockge, приложения TrueNAS) принимает compose-файл выше как есть —
поменяйте только путь `./data` на папку NAS. В Unraid удобнее шаблон: [INSTALL-UNRAID.ru.md](INSTALL-UNRAID.ru.md).

## Первые шаги на странице

1. Первые замеры появляются примерно через минуту. Язык (русский / английский) и стиль (Classic / UniFi) — в шапке страницы.
2. *Настройки → Интеграции*: включите Telegram, чтобы получать сообщения (см. [Уведомления](#уведомления)).
3. Вкладка *Speedtest*: выберите сервис (Fast.com, Cloudflare или Ookla) и при желании расписание (например каждую ночь в 04:00).
4. *Настройки*: по желанию «Показывать мой внешний IP и провайдера» и «Хранить историю», чтобы ограничить срок хранения.

## Проверка

```sh
docker ps --format '{{.Names}} {{.Status}}' | grep InternetHealth          # через несколько минут "(healthy)"
curl -s http://127.0.0.1:8788/api/about                                    # {"name":"Internet Health","version":"…"}
curl -s http://127.0.0.1:8788/api/health                                   # {"status":"ok", …}
docker logs InternetHealth 2>&1 | tail -20                                 # строки проб, без "Traceback"
```

Чтобы увидеть настоящую тревогу, выньте интернет-кабель из роутера **минимум на 3 минуты**. Изменение должно подтвердиться в двух циклах проб
подряд (около 50 с каждый, около 100 с без интернета), поэтому короткие перерывы считаются случайными — их ловит *Turbo-режим* в порогах (от ~10 с).
Придёт одно сообщение «Нет интернета», а после возвращения кабеля — одно «всё в порядке» с длительностью.

## Уведомления

*Настройки → Интеграции* включают каждый канал отдельно; история и графики ведутся всегда.

- **Telegram** — работает на любой машине, ставить ничего не нужно: создайте бота у @BotFather, добавьте его в свой чат, введите токен и ID чата,
  «Отправить тест», «Сохранить». Подробно: [NOTIFICATIONS.md](NOTIFICATIONS.md#integrations-unraid-and-telegram) (на английском).
- **Unraid** (почта и все агенты Unraid) — только на Unraid, через небольшой скрипт на хосте: [INSTALL-UNRAID.ru.md → Уведомления](INSTALL-UNRAID.ru.md#уведомления).

Пока интернета нет, сообщения ждут в очереди и уходят, когда он вернётся (с пометкой, на сколько опоздали).

## Обновление

```sh
docker compose pull && docker compose up -d          # compose
# docker run: docker pull ghcr.io/d1-m4ss/internet-health:latest, затем удалите контейнер и запустите той же командой
```

Версии и их описание: [GitHub Releases](https://github.com/d1-m4ss/internet-health/releases), [CHANGELOG](../CHANGELOG.md) (на английском); номер версии
— в подвале страницы. Папка данных не меняется, новая функция остаётся выключенной, пока вы её не включите. После обновления обновите страницу
Ctrl+F5. Чтобы остаться на версии, укажите тег, например `:1.4.0`, вместо `:latest`; откат — запуск предыдущего тега на той же папке.

С 1.4.0 приложение работает от `99:100`, а не от root; первый запуск после обновления со старой версии отдаёт файлы папки данных этому
пользователю (одна строка `entrypoint: handing files …` в логе).

## Копии и восстановление

*Настройки → История → Создать копию* делает согласованную копию базы, пока мониторинг работает (`<данные>/db-backups/`, хранятся 5 последних;
скачать или удалить — там же). Вернуться к копии:

```sh
docker stop InternetHealth
cp -p data/netprobe.sqlite data/netprobe.sqlite.before-restore          # сохранить текущую
rm -f data/netprobe.sqlite-wal data/netprobe.sqlite-shm                 # хвосты старого файла нельзя применять к копии
cp -p data/db-backups/netprobe-<дата>-<время>.sqlite data/netprobe.sqlite
docker start InternetHealth
```

Что лежит в папке данных (имена файлов остались от истории проекта и сохранены для совместимости):

```
data/
├── netprobe.sqlite          ← база (история, результаты Speedtest, очередь сообщений)
├── alert-settings.json      ← пороги тревог
├── netprobe-prefs.json      ← настройки Speedtest, внешнего IP, истории и интеграций со страницы
├── telegram.json            ← токен и чат Telegram (права 600), если заданы на странице
├── db-backups/              ← копии, сделанные со страницы
├── ookla/                   ← программа Ookla, только после первого теста Ookla
└── notify-token, *-state.json …   ← небольшие файлы состояния
```

Папка и её копии — личные данные: в них история, ваши внешние IP-адреса и токен Telegram.

## Удаление

`docker rm -f InternetHealth` (или `docker compose down`), затем удалите папку данных, если история не нужна.

## Сборка из исходников

`docker build -t internet-health:dev .` в клоне репозитория (базовый образ закреплён по digest, пакеты — в `requirements.txt`), затем используйте образ
`internet-health:dev`. Тестам нужен только `pip install -r requirements.txt`: `python -m unittest discover -s tests`.

## Если что-то не так

| Признак | Что проверить |
|---|---|
| Страница не открывается | сопоставление портов (`docker ps`: `0.0.0.0:8788->8080`), файрвол на машине, адрес, который вы открываете |
| `unhealthy` в `docker ps` | `curl http://127.0.0.1:8788/api/health` скажет почему: `503` с последней ошибкой, если цикл проб не сохранялся дольше интервала плюс пять минут; `docker logs InternetHealth` |
| `no matching manifest for linux/arm64` или `exec format error` | машина на ARM (Raspberry Pi, ARM-NAS): образ пока только для x86-64 |
| `Permission denied` / `readonly database` | папка данных должна быть доступна на запись `PUID:PGID` (по умолчанию 99:100); контейнер сам меняет владельца при старте, если не запущен с `--user`; на сетевых папках, которые запрещают `chown`, укажите `PUID=0` |
| Нет сообщений в Telegram | *Настройки → Интеграции*: включён ли Telegram? «Отправить тест» и строка состояния под ним (очередь, последняя ошибка) |
| После обновления страница не изменилась | Ctrl+F5; проверьте версию в подвале |
