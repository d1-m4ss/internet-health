# Internet Pulse

Расширение для [NetProbe](https://github.com/bmartino1/NetProbe_Python) на Unraid: история по каждой цели, отчёт о
потерях пакетов и **понятные уведомления Unraid** (email / Telegram) для Docker-контейнера NetProbe, плюс современный дашборд в двух стилях
(тёмный *NetProbe* и светлый/тёмный *UniFi*) с переключением русский/английский.

Это **расширение, а не форк контейнера**: оригинальный образ не меняется, поверх него монтируются три файла
только для чтения. Уберёте монтирования — вернётся штатный NetProbe.

> Internet Pulse — независимый проект, не связанный с автором NetProbe и не одобренный им. На скриншотах вымышленные
> данные (условный роутер ASUS, 192.168.1.1), их создаёт [`tests/demo_server.py`](tests/demo_server.py).

## Что даёт

- **История по каждой цели и измеренному IP** (SQLite, отдельные таблицы `np_*`, таблицы апстрима не трогаются).
- **Уведомления, которые объясняют проблему:** «Роутер не отвечает», «Нет интернета», «Не резолвятся имена (DNS)»,
  «Недоступно: Google» — с иконками, подсказкой что проверить и длительностью проблемы при восстановлении.
- **Без потока сообщений:** подтверждение по 2 замерам подряд, постоянная проблема — одно сообщение, «дрожащая» цель
  глушится одной сводкой. За 3 часа дрожания приходит 5–6 сообщений вместо сотен.
- **Turbo-режим (по желанию) для коротких обрывов:** лёгкий наблюдатель каждые 5 с пингует роутер и два IP в
  интернете и сообщает об обрывах от ~10 с, которые обычные проверки пропускают: одно сообщение после восстановления с
  длительностью, не более 3 в час, и тишина, если обычный мониторинг уже прислал тревогу. По умолчанию выключен;
  кнопка ⓘ в настройках объясняет, что он делает.
- **Плановый Speedtest с уведомлением.** Во вкладке *Speedtest*: выключено, каждые N часов или каждый день в заданное
  время (например 03:00); по желанию одно уведомление Unraid с результатом (или причиной ошибки) после каждого
  автоматического теста. Пока ничего не менять, расписание задают переменные контейнера `SPEEDTEST_ENABLED` /
  `SPEEDTEST_INTERVAL`, как раньше.
- **Карточка *WAN / провайдер* с внешним IP по желанию.** Галка *Показывать мой внешний IP и провайдера* в настройках —
  и под баннером состояния появится карточка с адресом, под которым вас видит интернет, и именем провайдера. По
  умолчанию выключено: пока галки нет, ничего не запрашивается и не записывается; с галкой контейнер
  спрашивает `api.ipify.org` об адресе (один крошечный запрос), а `ipwho.is` — об имени провайдера только при смене адреса
  и раз в сутки. Как часто — решаете вы: раз в 15 минут (по умолчанию), раз в минуту или **вручную** — тогда ничего не
  запрашивается, пока вы не нажмёте «Обновить» в карточке (в ручном режиме история WAN не пишется и уведомления о смене
  не отправляются). Сервисы видят адрес, с которого идёт запрос.
- **История WAN и селектор WAN-источника.** С этой галкой каждый замер сохраняется вместе с адресом и провайдером, через
  которые он прошёл, поэтому переключение на резервный канал или смену провайдера видно в данных: селектор
  «WAN-источник» над графиком и в таблице целей (синхронизированы) показывает историю, статистику и разбивку по целям
  для одного источника (общая оценка качества для отдельного WAN не рисуется — она относится ко всей сети). Записанные
  адреса удаляются вместе с историей по сроку хранения или сразу кнопкой «Забыть адреса WAN…». Выбранные период, WAN-источник
  и метрика запоминаются в браузере, поэтому в следующий раз всё откроется как вы оставили.
- **Telegram напрямую из контейнера (по желанию).** Настройки → *Telegram*: токен бота (у @BotFather) и ID чата, «Отправить
  тест», «Сохранить». Контейнер отправляет в чат через Bot API те же сообщения, что получает Unraid (тревоги, восстановление,
  смена WAN, результаты Speedtest) — вместе с мостом Unraid или без него. Токен хранится в `/data/telegram.json` (права 600),
  интерфейс и API его больше не показывают; можно передать его переменными `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`. Сообщения,
  созданные до включения, не отправляются; неудачная доставка повторяется с растущей паузой и бросается через сутки.
- **Уведомление о смене WAN.** По желанию: одно сообщение Unraid «было → стало» — предупреждение при смене провайдера
  (обычно переключение на резервный канал), информационное при смене только адреса; подтверждается двумя проверками подряд,
  не более 6 в час.
- **Срок хранения истории (по умолчанию выключен).** Без настройки база растёт бесконечно. В настройках можно выбрать
  хранение 7 / 30 / 90 / 180 дней или 1 год: более старые записи (проверки целей, DNS, события, Speedtest, доставленные
  уведомления) удаляются раз в ночь небольшими порциями, после чего файл сжимается. Можно также посмотреть, сколько
  будет удалено, и удалить сразу — с подтверждением и числом записей. Недоставленные уведомления, незавершённые
  обрывы и текущее состояние не удаляются никогда. Удаление необратимо: сделайте копию базы заранее.
- **Отчёт о потерях пакетов за любой период** (от 1 минуты до месяца или свой интервал «с–по»): сводка, таблица по
  целям и список эпизодов; клик по эпизоду приближает график.
- **Режим сравнения:** несколько метрик и целей (например все DNS-серверы) на одном графике.
- **Путь до интернета:** Unraid → роутер → Интернет по реальным целям, задержки на связях.
- **Выбор сервиса Speedtest.** Во вкладке *Speedtest* видно, чем именно измеряется скорость: Speedtest.net (серверы
  Ookla через speedtest-cli — по умолчанию), официальный Ookla CLI (если положить бинарник в контейнер) или
  **Fast.com (Netflix)** — его NetProbe измеряет сам, без аккаунта, ключа и доп. программ. Выбор действует для ручных и
  плановых тестов и хранится в `/data/netprobe-prefs.json`.
- **Два стиля, два языка** — выпадающие списки. Один HTML-файл без CDN и внешних шрифтов.
- **Безопасно:** сообщения идут только через штатный `notify` Unraid и, если вы настроили, в ваш Telegram-чат. Остальные
  внешние запросы — только те, которые вы включили: запускаемый или плановый Speedtest (серверы speedtest.net, Ookla или fast.com / Netflix — по
  выбранному сервису) и, только с галкой, определение публичного IP. Контейнеру не нужны привилегии, Docker-сокет и
  монтирование хоста.

## Требования

Unraid с контейнером **NetProbe** из Community Applications (`bmmbmm01/netprobe`, SQLite), настроенные уведомления
Unraid (email и/или Telegram), на хосте `curl`, `jq`, `flock`. Проверено на образе
`bmmbmm01/netprobe@sha256:386bdc2c177b11aef4a1223dfd91ae47fe2f9804c5449c5f4c2caae1d048c155`.

## Установка

**Проще всего — готовый образ** (с первого релиза): *Add Container* в Unraid по шаблону
[`docs/unraid/internet-pulse.xml`](docs/unraid/internet-pulse.xml) (образ `ghcr.io/d1-m4ss/netprobe-enhanced`) или
[`examples/docker-compose.image.yml`](examples/docker-compose.image.yml). Ничего копировать и монтировать не нужно; переезд с
текущей установки сохраняет данные — см. **[docs/INSTALL-UNRAID.md → Install the ready image](docs/INSTALL-UNRAID.md#install-the-ready-image-recommended)**
(на английском). Дальше в разделе — способ с монтированием файлов.

Установка с нуля (пример `docker-compose.yml`, затем три файла в папке данных): **[docs/INSTALL-COMPOSE.md](docs/INSTALL-COMPOSE.md)**.
Подробное руководство для уже работающего контейнера (проверки, откат, обновление образа): **[docs/INSTALL-UNRAID.md](docs/INSTALL-UNRAID.md)**. Оба на английском.
Коротко: резервная копия → закрепить образ по дайджесту → скопировать `src/app.py`, `src/netprobe_extensions.py`,
`src/index.html` в `/mnt/user/appdata/netprobe_database/custom/` и примонтировать их **только на чтение** в
`/app/app.py`, `/app/netprobe_extensions.py`, `/app/templates/index.html` → поставить мост уведомлений
(`src/netprobe-unraid-notify.sh` + строка cron из `scripts/netprobe-notify.cron`).

Рекомендуемые переменные контейнера: `ROUTER_IP`, `ROUTER_NAME` (подпись роутера, например `ASUS RT-AX86U`) и **две IP-цели в
`SITES`** (например `fast.com,google.com,youtube.com,1.1.1.1,8.8.8.8`): пинг по имени зависит от DNS, а цели по IP
позволяют отличить «упал DNS» от «нет интернета».

## Обновление с предыдущей версии

Новый релиз меняет только три файла контейнера. База, `alert-settings.json`, `notify-token`, скрипт моста и строка cron
остаются как есть, миграция не нужна (новые таблицы и файлы создаются при первом использовании). Сохраните старые
файлы, скопируйте новые в `…/custom/` и перезапустите контейнер — команды, проверка и откат в
**[docs/INSTALL-UNRAID.md → Updating Internet Pulse](docs/INSTALL-UNRAID.md#updating-internet-pulse)** (на английском).
Что менялось в каждой версии: [CHANGELOG.md](CHANGELOG.md).

## Тесты и проверка сбоев без отправки чего-либо

```sh
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python -m unittest discover -s tests
python tests/simulate_network.py -v     # настоящий цикл проб, очередь и мост на виртуальных часах; наружу ничего не уходит
npm install && npx playwright install chromium && node tests/test_ui.cjs
node tests/test_mobile_nav.cjs && node tests/test_speedtest_ui.cjs     # закреплённое меню на телефоне; сервис, расписание Speedtest и внешний IP
```

Посмотреть интерфейс без Unraid и без реальной сети: `python tests/demo_server.py` и открыть <http://127.0.0.1:8799>
(`--failing` — с аварией интернета в конце). Работает настоящее приложение на вымышленных данных;
`node tests/screenshots.cjs` пересоздаёт картинки в `docs/screenshots`.

## Безопасность и ограничения

Fast.com не имеет документированного публичного API: клиент использует те же адреса, что и страница fast.com. Если Netflix их
изменит, тест Fast.com завершится понятной ошибкой (а при включённых уведомлениях — предупреждением), остальные сервисы
работают как раньше.

Веб-интерфейс и API **без аутентификации** (как в апстриме) — держите порт 8788 в локальной сети. Очередь уведомлений
доступна только хосту по токену `/data/notify-token` (права 600). Пробы последовательные: цикл занимает ~50 с (при аварии ~100 с),
изменение должно подтвердиться в двух циклах подряд, поэтому обрыв короче ~1,5 минуты не будет замечен вообще, а
обрыв от ~2,5 минут замечается всегда (плюс до минуты на cron-мост). `confirm_samples = 1` снижает это до ~40 с, но
присылает уведомления и о единичных сбоях. **Turbo-режим** (по умолчанию выключен) ловит обрывы от ~10 с; цена —
около 9 МБ ICMP в сутки, а провайдер, ограничивающий ICMP сразу ко *всем* интернет-целям, может вызвать ложное
сообщение (одного потерянного эха или одного молчащего адреса недостаточно). Сообщение Turbo ждёт окончания цикла
обычных проверок, шедшего в момент восстановления (до ~1,5 мин), чтобы один обрыв не пришёл дважды. Если полностью недоступны и интернет, и сеть, Unraid не сможет отправить
письмо/Telegram. Реальная доставка через агентов Unraid проверится вашим первым настоящим событием; автотесты используют
фиктивный `notify`. Workflow GitHub Actions ещё не запускался.
