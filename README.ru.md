# Internet Health

Мониторинг домашнего интернета в одном Docker-контейнере: круглосуточно проверяет роутер, интернет и DNS, хранит историю по каждой цели,
объясняет обрывы **понятными сообщениями** в Telegram (или Unraid), по расписанию измеряет скорость через Fast.com, Cloudflare или Ookla и
показывает всё на дашборде в двух стилях с переключением русский/английский.

Работает на любой постоянно включённой машине x86-64 с Docker — мини-ПК, NAS (Synology, QNAP, TrueNAS, OpenMediaVault, Unraid), виртуальная машина
Proxmox или компьютер с Docker Desktop. Образ — `ghcr.io/d1-m4ss/internet-health`: запускаете, открываете веб-страницу и всё настраиваете там.

> На скриншотах вымышленные данные (условный роутер ASUS, 192.168.1.1), их создаёт [`tests/demo_server.py`](tests/demo_server.py).

## Быстрый старт

```sh
docker run -d --name InternetHealth --restart unless-stopped -p 8788:8080 -v ~/internet-health:/data \
  -e TZ=Europe/Moscow -e APP_TIMEZONE=Europe/Moscow -e ROUTER_IP=192.168.1.1 \
  -e SITES=fast.com,google.com,youtube.com,1.1.1.1,8.8.8.8 \
  ghcr.io/d1-m4ss/internet-health:latest
```

Откройте `http://<эта машина>:8788`, затем *Настройки → Интеграции*, чтобы получать сообщения в Telegram. Полная инструкция с docker compose,
интерфейсами NAS, обновлением и копиями: **[docs/INSTALL.ru.md](docs/INSTALL.ru.md)**; Unraid (шаблон и уведомления Unraid):
**[docs/INSTALL-UNRAID.ru.md](docs/INSTALL-UNRAID.ru.md)**.

## Что даёт

- **История по каждой цели и измеренному IP** в SQLite: роутер, сайты в интернете, DNS-серверы — потери, задержка, джиттер, время DNS. Ничего не
  удаляется, пока вы не выберете срок хранения.
- **Сообщения, которые объясняют проблему:** «Роутер не отвечает», «Нет интернета», «Не резолвятся имена (DNS)», «Недоступно: Google» — с иконками,
  подсказкой, что проверить, и длительностью проблемы при восстановлении. См. [docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md) (на английском).
- **Без потока сообщений:** изменение подтверждается двумя замерами подряд, постоянная проблема — одно сообщение, «дрожащая» цель глушится одной
  сводкой. За 3 часа дрожания приходит 5–6 сообщений вместо сотен.
- **Сообщения переживают обрыв:** пока интернета нет, они ждут в очереди и уходят, когда он вернётся, с пометкой, на сколько опоздали.
- **Turbo-режим (по желанию) для коротких обрывов:** лёгкий наблюдатель каждые 5 с пингует роутер и два IP в интернете и сообщает об обрывах
  от ~10 с, которые обычные проверки пропускают: одно сообщение после восстановления с длительностью, не больше 3 в час. По умолчанию выключен.
- **Speedtest: три сервиса, расписание и график.** **Fast.com** (по умолчанию) и **Cloudflare** измеряются самим приложением — без аккаунта, ключа и
  доп. программ; **Ookla** (серверы Speedtest.net) работает через официальную программу Ookla, которую первый тест Ookla скачивает в папку данных, —
  выбор этого сервиса означает согласие с условиями Ookla (личное некоммерческое использование). Каждый тест сохраняет скачивание, отдачу,
  задержку, джиттер и задержку под нагрузкой (bufferbloat; Ookla — ещё и потери). Тесты вручную или по расписанию (выключено / каждые N часов /
  каждый день в заданное время), сообщение после каждого и предупреждение, если скорость упала на 20 / 30 / 50 % ниже медианы за 7 дней того же
  сервиса. График показывает скорость, задержку и потери на одной оси времени, с кнопкой на каждую линию, один сервис или все (у каждого свой вид)
  и подсказкой при наведении.
- **Карточка *WAN / провайдер* с внешним IP по желанию.** По умолчанию выключено: пока нет галки «Показывать мой внешний IP и провайдера», ничего не
  запрашивается и не пишется; с галкой контейнер спрашивает `api.ipify.org` об адресе и `ipwho.is` об имени провайдера при смене — раз в 15 минут,
  раз в минуту или только по кнопке «Обновить».
- **История WAN и селектор источника.** С этой галкой каждый замер сохраняется вместе с адресом и провайдером, через которые он прошёл, поэтому
  переключение на резервный канал или смену провайдера видно в данных: селектор «WAN-источник» ограничивает график, таблицу целей и отчёт о потерях
  одним источником, отчёт о потерях сравнивает источники, а сравнение рисует по линии на источник. По желанию — сообщение о смене внешнего IP или провайдера.
- **Отчёт о потерях пакетов за любой период** (от 1 минуты до месяца или свой интервал «с–по»): сводка, таблица по целям и список эпизодов; клик по
  эпизоду приближает график.
- **Режим сравнения:** несколько метрик и целей (например все DNS-серверы) на одном графике.
- **Путь до интернета:** сервер → роутер → Интернет по реальным целям, с задержками на связях.
- **Уведомления туда, куда нужно.** *Настройки → Интеграции*: **Telegram** прямо из контейнера (на любой машине), **Unraid** (почта и все агенты
  Unraid через небольшой скрипт на хосте Unraid), оба или ни одного — история и графики ведутся всегда. Токен Telegram хранится с правами 600 и
  больше нигде не показывается.
- **Копии базы и срок хранения.** «Создать копию» делает согласованную копию, пока мониторинг работает (хранятся 5 последних, их можно скачать).
  «Хранить историю» 7 / 30 / 90 / 180 дней или 1 год удаляет старые записи раз в ночь; по умолчанию выключено.
- **Три стиля (Classic, UniFi, Control), светлая / тёмная / авто тема, два языка**, вёрстка для телефона с закреплённым меню в одну строку. Одна HTML-страница без CDN и внешних шрифтов,
  работает в локальной сети без интернета.
- **Осторожно по умолчанию.** Работает от непривилегированного пользователя (99:100, если не выбрать другого), не нужны Docker-сокет, особые права
  и монтирование хоста, кроме папки данных. Наружу уходят только пробы, Speedtest, который вы запускаете или запланировали, настроенные вами
  сообщения и — только с галкой — определение внешнего IP.

## Требования

- Постоянно включённая машина с Docker в одной сети с роутером (лучше по кабелю), **x86-64 (amd64)** — ARM (Raspberry Pi, NAS на ARM) пока не поддерживается.
- Для страницы, истории, Speedtest и Telegram больше ничего не нужно. Для уведомлений Unraid нужен ещё небольшой скрипт на хосте Unraid.

Образ собирается из `Dockerfile` этого репозитория на `python:3.14-slim`, закреплённом по digest; все пакеты Python закреплены в `requirements.txt`,
Dependabot раз в неделю предлагает новые версии, CI собирает и запускает образ при каждом изменении.

## Обновление

Версии нумеруются ([semver](https://semver.org)), у каждой есть описание на [странице релизов](https://github.com/d1-m4ss/internet-health/releases) и в
[CHANGELOG.md](CHANGELOG.md); номер виден в подвале страницы и в `GET /api/about`. В compose — `docker compose pull && docker compose up -d`, в Unraid —
*Check for updates → Update*. Папка данных не затрагивается, новая функция остаётся выключенной, пока вы её не включите. Чтобы остаться на версии,
укажите тег, например `:1.4.0`. Подробно: [docs/INSTALL.ru.md → Обновление](docs/INSTALL.ru.md#обновление).

## Настройка

| Переменная контейнера | Значение |
|---|---|
| `ROUTER_IP` | адрес роутера; становится узлом *Роутер* и первым подозреваемым, если не отвечает |
| `ROUTER_NAME` | имя роутера на странице и в сообщениях (по умолчанию `Router`, например `ASUS RT-AX86U`) |
| `SITES` | цели для пинга через запятую; добавьте 1–2 IP-адреса к именам (по умолчанию `fast.com,google.com,youtube.com`) |
| `DNS_NAMESERVER_n` / `_IP` | проверяемые DNS-серверы, `n` = 1–4 (по умолчанию Google, Quad9, Cloudflare) |
| `DNS_TEST_SITES` | имена, которые резолвятся на каждом DNS-сервере (по умолчанию `google.com`) |
| `PROBE_INTERVAL`, `PING_COUNT`, `PING_WAIT` | пауза между циклами проб (по умолчанию 30 с), пингов на цель (4), сколько секунд ждать последний ответ ping (2) |
| `SPEEDTEST_ENABLED`, `SPEEDTEST_INTERVAL`, `SPEEDTEST_BACKEND` | плановые тесты, их интервал в секундах и сервис (`fast` — по умолчанию, `cloudflare` или `ookla`); вкладка *Speedtest* переопределяет сервис и расписание |
| `TZ`, `APP_TIMEZONE` | часовой пояс контейнера и ежедневного времени Speedtest (по умолчанию `UTC`) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | необязательно: Telegram без формы на странице (нужны оба; важнее сохранённых значений) |
| `PUID`, `PGID` | пользователь, от которого работает приложение (по умолчанию `99` и `100`); контейнер стартует от root только чтобы отдать ему папку данных, затем сбрасывает права. `PUID=0` — работать от root |
| `WEIGHT_*`, `THRESHOLD_*` | веса и пределы оценки качества 0–100 |
| `GUNICORN_CMD_ARGS` | уже `--threads 4`; не увеличивайте `--workers`: каждый воркер запустит свой цикл проб |

Пороги тревог (потери ≥ 10 %, RTT ≥ 150 мс, джиттер ≥ 80 мс, DNS ≥ 250 мс, 2 замера для тревоги, 2 для восстановления) меняются на странице
(*Пороги уведомлений*) или в `/data/alert-settings.json`.

## Тесты и проверка сбоев без отправки чего-либо

```sh
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python -m unittest discover -s tests
python tests/simulate_network.py -v     # настоящий цикл проб, очередь и мост на виртуальных часах; наружу ничего не уходит
npm install && npx playwright install chromium && node tests/test_ui.cjs
node tests/test_mobile_nav.cjs && node tests/test_speedtest_ui.cjs     # закреплённое меню на телефоне; Speedtest, расписание и внешний IP
```

Симулятор прогоняет 20 сценариев сбоев (обрыв, отказ только DNS, роутер не отвечает, «дрожание», перезапуски, сломанный отправитель…) через
настоящий код; **настоящих сообщений и сетевых запросов нет**. Посмотреть страницу без реальной сети: `python tests/demo_server.py` и открыть
<http://127.0.0.1:8799> (`--failing` — с аварией интернета в конце). Работает настоящее приложение на вымышленных данных;
`node tests/screenshots.cjs` пересоздаёт картинки в `docs/screenshots`.

## Безопасность и ограничения

- У страницы и API **нет входа по паролю** — держите порт 8788 в локальной сети и никогда не открывайте наружу. Любой, кто открыл страницу, может
  менять настройки (в том числе Telegram) и скачивать копии базы.
- Очередь сообщений для Unraid доступна только хосту по токену `/data/notify-token` (права 600).
- Пробы последовательные: цикл занимает ~50 с (при аварии ~100 с), изменение должно подтвердиться в двух циклах подряд, поэтому обрыв короче
  ~1,5 минуты обычные проверки не заметят, а обрыв от ~2,5 минут заметят всегда. **Turbo-режим** (по умолчанию выключен) ловит обрывы от ~10 с; цена —
  около 9 МБ ICMP в сутки, а провайдер, ограничивающий ICMP сразу ко *всем* интернет-целям, может вызвать ложное сообщение.
- Цифры **Fast.com** и **Cloudflare** — от собственного клиента приложения (задержка, затем 8 соединений на 8 с вниз и 4 на 8 с вверх); они могут
  отличаться от страниц сервисов, поэтому сравнивайте сервис сам с собой во времени. Тест занимает канал примерно на 20 с.
- Fast.com и Cloudflare не гарантируют адреса, которые использует их страница; если они изменятся, этот сервис завершится понятной ошибкой, остальные
  продолжат работать. Программа Ookla — версия 1.2.0 для Linux, условия её использования — условия Ookla.
- Если не работает вся сеть, ничего не уйдёт наружу, пока она не вернётся (сообщения ждут в очереди); чтобы узнать о полном отключении в моменте,
  нужен внешний наблюдатель.
