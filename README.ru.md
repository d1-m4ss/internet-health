# NetProbe Enhanced

Расширение для [NetProbe](https://github.com/bmartino1/NetProbe_Python) на Unraid: история по каждой цели, отчёт о
потерях пакетов и **понятные уведомления Unraid** (email / Telegram) для Docker-контейнера NetProbe, плюс современный дашборд в двух стилях
(тёмный *NetProbe* и светлый/тёмный *UniFi*) с переключением русский/английский.

Это **расширение, а не форк контейнера**: оригинальный образ не меняется, поверх него монтируются три файла
только для чтения. Уберёте монтирования — вернётся штатный NetProbe.

> NetProbe Enhanced — независимый проект, не связанный с автором NetProbe и не одобренный им. На скриншотах вымышленные
> данные (условный роутер ASUS, 192.168.1.1), их создаёт [`tests/demo_server.py`](tests/demo_server.py).

## Что даёт

- **История по каждой цели и измеренному IP** (SQLite, отдельные таблицы `np_*`, таблицы апстрима не трогаются).
- **Уведомления, которые объясняют проблему:** «Роутер не отвечает», «Нет интернета», «Не резолвятся имена (DNS)»,
  «Недоступно: Google» — с иконками, подсказкой что проверить и длительностью проблемы при восстановлении.
- **Без потока сообщений:** подтверждение по 2 замерам подряд, постоянная проблема — одно сообщение, «дрожащая» цель
  глушится одной сводкой. За 3 часа дрожания приходит 5–6 сообщений вместо сотен.
- **Turbo-режим (по желанию) для коротких обрывов:** лёгкий наблюдатель каждые 5 с пингует роутер и два IP в
  интернете и сообщает об обрывах от ~10 с, которые обычные проверки пропускают: одно сообщение после восстановления с
  длительностью, не более 3 в час, и тишина, если обычный мониторинг уже прислал тревогу. По умолчанию выключен;
  кнопка ⓘ в настройках объясняет, что он делает.
- **Отчёт о потерях пакетов за любой период** (от 1 минуты до месяца или свой интервал «с–по»): сводка, таблица по
  целям и список эпизодов; клик по эпизоду приближает график.
- **Режим сравнения:** несколько метрик и целей (например все DNS-серверы) на одном графике.
- **Путь до интернета:** Unraid → роутер → Интернет по реальным целям, задержки на связях.
- **Текущий внешний IP и провайдер:** дашборд показывает публичный адрес и провайдера, видимые для исходящего трафика NetProbe; это помогает понять, какой WAN роутера сейчас работает. Таблица целей и график истории соединения используют общий список WAN (по умолчанию выбран текущий), а статистика показывается только для проб выбранного провайдера. Для прежних замеров, сделанных до этого обновления, источник явно отмечен как незаписанный. График выбранного WAN не показывает общую оценку качества, так как её нельзя достоверно отнести к одному провайдеру. Адрес может отличаться от адреса интерфейса роутера (например, при CGNAT). Данные обновляются каждые 30 секунд.
- **Два стиля, два языка** — выпадающие списки. Один HTML-файл без CDN и внешних шрифтов.
- **Минимальный внешний запрос:** каждые 30 секунд сервер NetProbe по HTTPS запрашивает у `ipwho.is` публичный IP исходящего соединения и сведения о провайдере. Сервис неизбежно видит IP-адрес источника запроса. Проверки сети и отправка уведомлений остаются без изменений; контейнеру не нужны дополнительные привилегии, Docker-сокет
  и монтирование хоста.

## Требования

Unraid с контейнером **NetProbe** из Community Applications (`bmmbmm01/netprobe`, SQLite), настроенные уведомления
Unraid (email и/или Telegram), на хосте `curl`, `jq`, `flock`. Проверено на образе
`bmmbmm01/netprobe@sha256:386bdc2c177b11aef4a1223dfd91ae47fe2f9804c5449c5f4c2caae1d048c155`.

## Установка

Установка с нуля (пример `docker-compose.yml`, затем три файла в папке данных): **[docs/INSTALL-COMPOSE.md](docs/INSTALL-COMPOSE.md)**.
Подробное руководство для уже работающего контейнера (проверки, откат, обновление образа): **[docs/INSTALL-UNRAID.md](docs/INSTALL-UNRAID.md)**. Оба на английском.
Коротко: резервная копия → закрепить образ по дайджесту → скопировать `src/app.py`, `src/netprobe_extensions.py`,
`src/index.html` в `/mnt/user/appdata/netprobe_database/custom/` и примонтировать их **только на чтение** в
`/app/app.py`, `/app/netprobe_extensions.py`, `/app/templates/index.html` → поставить мост уведомлений
(`src/netprobe-unraid-notify.sh` + строка cron из `scripts/netprobe-notify.cron`).

Рекомендуемые переменные контейнера: `ROUTER_IP`, `ROUTER_NAME` (подпись роутера, например `ASUS RT-AX86U`) и **две IP-цели в
`SITES`** (например `fast.com,google.com,youtube.com,1.1.1.1,8.8.8.8`): пинг по имени зависит от DNS, а цели по IP
позволяют отличить «упал DNS» от «нет интернета».

## Тесты и проверка сбоев без отправки чего-либо

```sh
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python -m unittest discover -s tests
python tests/simulate_network.py -v     # настоящий цикл проб, очередь и мост на виртуальных часах; наружу ничего не уходит
npm install && npx playwright install chromium && node tests/test_ui.cjs
```

Посмотреть интерфейс без Unraid и без реальной сети: `python tests/demo_server.py` и открыть <http://127.0.0.1:8799>
(`--failing` — с аварией интернета в конце). Работает настоящее приложение на вымышленных данных;
`node tests/screenshots.cjs` пересоздаёт картинки в `docs/screenshots`.

## Безопасность и ограничения

Веб-интерфейс и API **без аутентификации** (как в апстриме) — держите порт 8788 в локальной сети. Очередь уведомлений
доступна только хосту по токену `/data/notify-token` (права 600). Пробы последовательные: цикл занимает ~50 с (при аварии ~100 с),
изменение должно подтвердиться в двух циклах подряд, поэтому обрыв короче ~1,5 минуты не будет замечен вообще, а
обрыв от ~2,5 минут замечается всегда (плюс до минуты на cron-мост). `confirm_samples = 1` снижает это до ~40 с, но
присылает уведомления и о единичных сбоях. **Turbo-режим** (по умолчанию выключен) ловит обрывы от ~10 с; цена —
около 9 МБ ICMP в сутки, а провайдер, ограничивающий ICMP сразу ко *всем* интернет-целям, может вызвать ложное
сообщение (одного потерянного эха или одного молчащего адреса недостаточно). Сообщение Turbo ждёт окончания цикла
обычных проверок, шедшего в момент восстановления (до ~1,5 мин), чтобы один обрыв не пришёл дважды. Если полностью недоступны и интернет, и сеть, Unraid не сможет отправить
письмо/Telegram. Реальная доставка через агентов Unraid проверится вашим первым настоящим событием; автотесты используют
фиктивный `notify`. Workflow GitHub Actions ещё не запускался.
